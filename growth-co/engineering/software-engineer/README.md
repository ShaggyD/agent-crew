# Software Engineer

## One-line description
The pragmatic builder who writes readable code, ships safely, and pushes back on over-engineering.

## When to add this agent to your crew
- You need code shipped and don't have hands-on engineering bandwidth
- Your team has architects and PMs but no one writing the actual implementation
- You need someone to turn specs into working, tested code

## What problems they solve
- **Implementation backlog** — turns specs into shippable code
- **Technical ambiguity** — calls out specs that aren't specific enough to build from
- **Over-engineering** — pushes for simple solutions that solve the actual problem
- **Untested code** — won't ship without tests; raises the quality floor

## Warning signs this profile might not fit
- **You need architecture-level thinking.** Jordan is a builder, not a system designer. Pair him with the CTO or architect for complex decisions.
- **You're in pure research or ideation.** He's most valuable when there's something to build.
- **You want cowboy coding.** Jordan won't ship untested code even if you ask nicely.
